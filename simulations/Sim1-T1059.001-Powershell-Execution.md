## Executive Summary
* **Objective:** Simulate an adversary utilizing PowerShell to execute commands/scripts, ensure Windows 11 VM generates proper telemetry,
  and to confirm that Wash accurately triggers a high-severity alert.
* **Attack Overview:** This test loads the SharpHound collector directly into memory via a PowerShell download cradle to bypass disk scanning. While the execution itself is fileless, the tool automatically saves a compressed .zip file of its discovery findings to the local temp directory.
* **Detection Status:** Successful
* **Main Takeaway:** Sysmon successfully captured the command-line argument which in turn triggered Wazuh Rule 92213 (Level 15) for a suspicious PowerShell execution.

## Defense and Hardening Recommendations (Mitigation)
* **Applocker/Application Control:** Configure Applocker or Software Restriction Policies to deny execution of binaries and scripts running from '%Appdata%' and '%LocalAppData%\Temp%' paths. **Critical** While this will not prevent the tool from dropping a passive .zip data archive (Rule 92213), it ensures that any malicious executable payloads dropped into temporary folders are blocked from executing.
* **Constrained Language Mode (CLM):** **High** This will restrict PowerShell access to basic commands and block advanced .NET APIs, therefore neutralizing fileless download methods like 'Net.WebClient'.
* **Execution Policy:** Set the PowerShell execution policy to 'AllSigned' via GPO. **Medium** Note that this is a defense-in-depth measure; it stops local unsigned script files from running, but it does not natively block memory-only download cradles or commands executed via IEX.
* **Script Block Logging:** Enable Windows Event Log Event ID 4104 (PowerShell Script Block Logging). **High** This will capture the exact, decrypted content of executed PowerShell code blocks in the event log, allowing the analyst to review heavily obfuscated scripts.

## Customized Wazuh Detection Rule
Wazuh's default detection rules detected the basic PowerShell process creations, adversaries frequently execute code using inline script blocks '&{...}' to avoid writing ',ps1' files to disk. Due to this scenario, I created a custom Wazuh detection rule to target this inline execution method specifically.
