  and to confirm that Wash accurately triggers a high-severity alert.
* **Attack Overview:** This test checks if endpoint security (EDR/SIEM) can detect fileless execution and domain reconnaissance by using a PowerShell download cradle to load the SharpHound data collector directly into memory without saving it to disk.

## Defense and Hardening Reommendations (Mitigation)
* **Applocker/Application Control:** Configure Applocker or Software Restrictions Policies to deny execution of binaries and scripts
running from '%Appdata%' and '%\LocalSettings\Tempe%' path. **Critical** Even if an adversary uses PowerShell too drop a payload into the Tempe folder (Rule 92213), Applocker will block the payload from executing; ie. neutralizing the threat.
* **Constrained Language Mode (CLM):** Enforce PoweShell CLM via Group Policy Objects (GPO) or Applocker. **High** This will restrict PowerShell access to basic commands and block advanced .NET APIs, therefore neutralizing fileless download methods like'Net.Web.Client'.
* **Execution Policy:** Need to set the PoweShell execution policy to 'AllSigned' via GPAQ. **Medium** This will prevent ad-hoc, unsigned scripts from running directly on the filesystem, forcing adversaries to find alternative pathways for execution.
* **Script Block Logging:** Enable Windows Event Log Event ID 4104 (PowerShell Script Block Logging). **High** This will capture the exact, decrypted content of executed PowerShell code blocks in the event log, allowing the analyst to review heavily obfuscated scripts.

Due to this scenario, I created a custom Wazuh detection rule to target this inline execution method specifically.
